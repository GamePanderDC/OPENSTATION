# OpenStation Max: ручная установка, запуск и службы

Инструкция составлена по исходникам OpenStation Max 1.6.20. Здесь команды вводятся вручную, по одной: установочные `.bat`, `.ps1` и `.sh` запускать не нужно. Станция во время подготовки этой инструкции не была подключена к компьютеру, поэтому последовательность не проверена на живом устройстве. Состав служб и имена пакетов могут отличаться между версиями заводской системы.

## 1. Сначала разберёмся, что именно можно запустить

OpenStation работает поверх Android и заводских драйверов Яндекс Станции Макс `yandexstation_2`. Это не отдельная операционная система, запускаемая на пустом накопителе. Нужно, чтобы колонка уже загружалась в совместимый Android, работал root ADB, были исправны системные и аппаратные компоненты.

**Если колонка не загружается, ADB нет или память полностью пустая**, инструкции ниже недостаточно: сначала нужен совместимый загрузочный и системный образ, способ его записи и восстановление устройства. Команды ADB не заменяют USB Burning Tool и не восстанавливают загрузчик. Описание USB-установки — в [INSTALLER.md](INSTALLER.md). Не записывайте чужие индивидуальные ключи и не стирайте разделы с уникальными данными устройства.

В данном документе «с нуля» означает ручную установку компонентов OpenStation на уже работающую и совместимую Android-систему. Это **не** инструкция по сборке всей заводской прошивки или по гарантированному восстановлению колонки после бутлупа.

## 2. Как всё устроено

| Компонент | Для чего нужен | Что будет, если выключить |
|---|---|---|
| Android, его системные службы и драйверы производителя | Запуск приложений, доступ к устройствам, сеть, звук, Bluetooth, экран | Без них система или отдельное оборудование могут перестать работать. Не отключайте наугад. |
| `openstationd` | Центральный процесс: веб-пульт, настройки, ассистент, управление оборудованием и интеграции | OpenStation как система управления не работает; отдельные Android-приложения могут оставаться открыты. |
| OpenStation Launcher | Интерфейс на телевизоре, музыкальный плеер и его Android-сервис | Не будет интерфейса OpenStation на ТВ; также могут пропасть функции музыки и звука, связанные с `StationAudioService`. |
| OpenStation IME | Экранная клавиатура и ввод текста | Если есть другая рабочая клавиатура — она необязательна. |
| Модели VAD/KWS, ONNX и Sherpa | Определение речи и слова активации | Голосовая активация может перестать работать; сам веб-пульт не требует голосового запуска. |
| Gemini / альтернативный голосовой сервер | Обработка голосового диалога в выбранном режиме | Без выбранного и настроенного сервиса соответствующий голосовой режим не работает. Gemini требует сеть и действующий ключ. |
| Кольцо, матричный экран, визуализаторы | Индикация и оформление | В настройках можно выключить индикацию, не отключая системные драйверы. |
| Wyoming, MQTT, Home Assistant | Необязательная интеграция с домашней автоматизацией | Не работают соответствующие внешние интеграции. |
| OTA | Проверка и установка обновлений | При отключении автоматической проверки обновления нужно проверять вручную. |

Не путайте отключение эффекта в настройках OpenStation с остановкой аппаратного драйвера Android: это разные действия.

## 3. Что подготовить

1. Станцию Макс, загружающуюся в совместимый Android, и питание.
2. Windows-ПК, подключённый к той же сети, либо рабочее USB ADB-подключение.
3. Google Android Platform Tools с `adb.exe`, доступным в PowerShell. Если `adb` не найден, откройте PowerShell в папке Platform Tools и вместо `adb` пишите `.\adb.exe`.
4. Полную папку проекта соответствующей версии: в ней должны быть `firmware`, `assets\alice` и при необходимости `assets\ym_app.tar.gz`. Один только APK не содержит все компоненты. Используйте файлы одного выпуска и сверяйте их с `firmware\manifest.json`. В релизе набор ресурсов может отличаться; если файла нет, не подменяйте его случайной версией.
5. Рабочий root-доступ ADB. Он не появляется просто от установки OpenStation. Не открывайте root ADB в интернет: в локальной сети он даёт очень широкий доступ к колонке.

Пути ниже считаются относительно корня проекта. В PowerShell перейдите в него, подставив реальный путь:

```powershell
cd 'C:\путь\к\OPENSTATION'
adb version
```

Если станций несколько, выберите одну и добавляйте к каждой команде `adb -s СЕРИЙНЫЙ_НОМЕР ...`.

## 4. Проверка устройства до изменений

При сетевом подключении подставьте IP устройства; по USB эта команда не нужна:

```powershell
adb connect 192.168.1.50:5555
adb devices -l
adb shell id
adb shell getprop ro.product.device
adb shell getprop ro.product.cpu.abi
adb shell df -h /data
```

IP выше — пример. Нужен статус `device`, в `id` — `uid=0(root)`, модель должна соответствовать `yandexstation_2`, ABI — `arm64-v8a`. Если получаете `unauthorized`, `offline`, не root или иную модель, остановитесь и выясните причину. `adb root` поддерживается не всеми сборками; на обычном закрытом Android рассчитывать на него нельзя. Не продолжайте при нехватке места.

Проверьте файлы выпуска:

```powershell
Get-Content .\firmware\manifest.json
Get-FileHash .\firmware\openstationd -Algorithm SHA256
Get-FileHash .\firmware\OpenStationLauncher.apk -Algorithm SHA256
Get-FileHash .\firmware\OpenStationIME.apk -Algorithm SHA256
```

Сравните хэши с `sha256` у соответствующих файлов манифеста. Они должны совпасть. Манифест подтверждает целостность при условии, что сам он получен из доверенного выпуска; он не доказывает совместимость любой сборки с любой станцией. Ресурсы `assets` этим конкретным манифестом не охватываются.

### Резервные копии

На уже используемой станции сохраните настройки и сведения об автозапуске в закрытой папке на ПК:

```powershell
mkdir .\backup-manual
adb pull /data/local/openstation/config.json .\backup-manual\config.json
adb pull /vendor/bin/rc_local.sh .\backup-manual\rc_local.sh
adb shell pm list packages -d
adb shell pm list packages -e
```

Если файла ещё нет, `adb pull` сообщит об ошибке — для новой установки это возможно. Файл настроек может содержать ключи и токены: никому его не отправляйте и не выкладывайте в GitHub. Отдельно запишите, какие пакеты уже отключены, чтобы не включить их случайно при откате. Эти копии не являются полной резервной копией прошивки или уникальных данных устройства.

## 5. Ручное копирование компонентов

Команды ниже изменяют файлы на станции. Если OpenStation уже запущена, сначала сохраните конфигурацию и остановите процесс из раздела 9. Не заменяйте работающий бинарник без резервной копии. На новой установке создайте каталоги:

```powershell
adb shell mkdir -p /data/local/openstation/lib /data/local/openstation/models/ru-vosk-small
adb push .\firmware\openstationd /data/local/openstation/openstationd
adb push .\firmware\manifest.json /data/local/openstation/firmware_manifest.json
adb push .\assets\alice\lib\arm64-v8a\libonnxruntime.so /data/local/openstation/lib/
adb push .\assets\alice\lib\arm64-v8a\libsherpa-onnx-c-api.so /data/local/openstation/lib/
adb push .\assets\alice\models\silero_vad.int8.onnx /data/local/openstation/models/
adb push .\assets\alice\models\ru-vosk-small\encoder.int8.onnx /data/local/openstation/models/ru-vosk-small/
adb push .\assets\alice\models\ru-vosk-small\decoder.onnx /data/local/openstation/models/ru-vosk-small/
adb push .\assets\alice\models\ru-vosk-small\joiner.int8.onnx /data/local/openstation/models/ru-vosk-small/
adb push .\assets\alice\models\ru-vosk-small\tokens.txt /data/local/openstation/models/ru-vosk-small/
adb push .\assets\alice\cacert.pem /data/local/openstation/cacert.pem
adb shell chmod 755 /data/local/openstation/openstationd
adb shell chmod 755 /data/local/openstation/lib/libonnxruntime.so /data/local/openstation/lib/libsherpa-onnx-c-api.so
adb shell chmod 644 /data/local/openstation/firmware_manifest.json /data/local/openstation/cacert.pem /data/local/openstation/models/silero_vad.int8.onnx /data/local/openstation/models/ru-vosk-small/*
```

Если какая-либо команда `push` завершилась ошибкой, сначала исправьте её. `cacert.pem` содержит корневые сертификаты для проверок защищённых соединений; не стоит без понимания подменять его или выключать проверку сертификатов.

Архив музыкального интерфейса — дополнительный ресурс. Если он есть и нужна совместимая веб-часть, скопируйте его и распакуйте в **новый пустой** каталог. Не распаковывайте поверх существующей пользовательской папки:

```powershell
adb push .\assets\ym_app.tar.gz /data/local/openstation/ym_app.tar.gz
adb shell mkdir /data/local/openstation/ym_app
adb shell tar -xzf /data/local/openstation/ym_app.tar.gz -C /data/local/openstation/ym_app
adb shell chmod -R a+rX /data/local/openstation/ym_app
```

Если каталог уже существует, команда `mkdir` сообщит об этом: не продолжайте распаковку поверх него без сохранения прежней версии. Сам музыкальный плеер также использует Android-сервис внутри лаунчера; не предполагается обязательный отдельный Node.js-процесс.

## 6. Установка приложений

```powershell
adb install -r -g .\firmware\OpenStationLauncher.apk
adb install -r -g .\firmware\OpenStationIME.apk
adb shell pm list packages com.openstation
```

`-r` обновляет установленное приложение, `-g` запрашивает выдачу разрешений, которые Android разрешает выдать таким способом. `Success` означает установку APK, но не проверку звука и экрана. Если появляется ошибка несовпадения подписи, не удаляйте установленное приложение вслепую: удаление может стереть его данные. Сначала сохраните данные и найдите совместимый подписанный APK.

Для клавиатуры, если она нужна:

```powershell
adb shell ime list -s
adb shell ime enable com.openstation.ime/.OpenStationImeService
adb shell ime set com.openstation.ime/.OpenStationImeService
```

Перед переключением запишите прежний идентификатор клавиатуры из `ime list -s`. Вернуть его можно командой `adb shell ime set ИДЕНТИФИКАТ`. Если другая клавиатура подходит, этот шаг необязателен.

Для открытия интерфейса на телевизоре:

```powershell
adb shell am start -a android.intent.action.MAIN -c android.intent.category.HOME -n com.openstation.launcher/.MainActivity
```

Открытие приложения ещё не делает его домашним экраном навсегда. При желании выбрать его основным на поддерживаемой сборке:

```powershell
adb shell cmd package set-home-activity com.openstation.launcher/.MainActivity
```

До смены домашнего приложения запишите текущее значение в настройках Android. Команда зависит от версии Android; если она не поддерживается, используйте системный выбор домашнего приложения.

## 7. Ручной запуск

Проверьте, что демон уже не работает:

```powershell
adb shell pidof openstationd
```

Пустой ответ обычно означает, что процесса нет. Если PID уже есть, второй экземпляр не запускайте. Команда ниже задаёт пути поиска библиотек и запускает процесс в фоне:

```powershell
adb shell 'LD_LIBRARY_PATH=/data/local/openstation/lib:/vendor/lib64:/system/lib64 /data/local/openstation/openstationd --daemon'
adb shell pidof openstationd
adb shell tail -n 80 /data/local/openstation/boot.log
adb shell tail -n 80 /data/local/openstation/openstationd.log
```

При отсутствии `pidof` или `tail` на другой сборке используйте доступные средства диагностики. `boot.log` и `openstationd.log` могут содержать технические и персональные сведения — проверяйте их перед отправкой. Успешный вывод команды запуска не гарантирует, что процесс не завершился сразу; обязательно проверьте PID и журнал.

Узнайте IP станции в настройках сети Android либо командой:

```powershell
adb shell ip -4 addr show wlan0
```

Для Ethernet имя интерфейса может отличаться. На телефоне или ПК в той же сети откройте `http://IP-СТАНЦИИ:8080/`. Порт 8080 — значение по умолчанию, его могли изменить. Перейдите в настройки и настройте сеть, часовой пояс, звук и ассистента. Для Gemini нужен личный рабочий ключ и доступность сервиса; для Яндекс Музыки — отдельный вход в аккаунт. Не отправляйте ключи в общие чаты.

После этого проверьте отдельно веб-пульт, ТВ-интерфейс, звук, микрофон, кольцо, экран и Bluetooth-пульт. Факт запуска процесса не подтверждает исправность каждого из них.

## 8. Что происходит после перезагрузки

Ручная команда из раздела 7 запускает OpenStation **до остановки процесса или перезагрузки**. Копирование файлов и установка APK сами по себе не гарантируют автозапуск демона. В типовой установке проекта он добавляется в `/vendor/bin/rc_local.sh`, но здесь мы не создаём и не изменяем скрипты.

На уже настроенной станции проверьте состояние после перезагрузки:

```powershell
adb shell pidof openstationd
adb shell tail -n 80 /data/local/openstation/boot.log
```

Если PID отсутствует, запускайте демон вручную по разделу 7. Для постоянного запуска необходим совместимый с конкретной прошивкой механизм автозагрузки; его настройка требует отдельной проверки, иначе легко потерять доступ или нарушить загрузку. Наличие `rc_local.sh` на одной сборке не гарантирует его наличия или вызова на другой. Не меняйте `/vendor`, `init`, загрузчик и разделы методом догадок.

## 9. Как временно остановить и вернуть OpenStation

Сначала сохраните настройки. Остановка прервёт активные функции OpenStation:

```powershell
adb shell pidof openstationd
adb shell killall openstationd
adb shell pidof openstationd
```

Если процесс снова появляется, его может запускать механизм автозагрузки или наблюдения. Не удаляйте его и не убивайте системные процессы: выясните источник запуска. Чтобы снова включить демон, используйте раздел 7. `adb shell am force-stop com.openstation.launcher` отдельно останавливает лаунчер и его Android-сервисы, в том числе музыкальные; открыть его снова можно командой из раздела 6.

## 10. Службы Яндекса: что они делают и что отключать

**Сначала различайте Android-пакет и системную службу.** Пакет вида `com.yandex...` — установленное приложение с собственными компонентами. Служба `init.svc...` — часть запуска Android или производителя; у неё может быть то же слово Yandex в имени, но отключать её теми же командами нельзя. Имена сами по себе не доказывают назначение компонента.

Для инвентаризации на своей колонке:

```powershell
adb shell pm list packages | findstr /i yandex
adb shell pm list packages -d
adb shell pm list packages -e
adb shell getprop | findstr /i init.svc
adb shell ps -A | findstr /i yandex
```

Посмотреть конкретный пакет, его путь и состояние:

```powershell
adb shell pm path com.yandex.tv.alice
adb shell dumpsys package com.yandex.tv.alice
```

Если пакет не найден, на вашей прошивке его может не быть или он называется иначе. Вывод `dumpsys` длинный. Наличие процесса ещё не означает, что он безопасен для отключения.

### Можно рассмотреть для отключения, если функция не нужна

Ниже — пакеты из списка отключения существующего установщика OpenStation. Это **кандидаты**, а не гарантия безопасности для каждой ревизии: зависимости, версии и последствия нужно проверять. Отключайте по одному, проверяя звук, сеть, пульт, загрузку и возможность отката.

| Пакеты | Предполагаемая роль / последствие |
|---|---|
| `com.yandex.tv.home` | Заводской домашний экран. Можно рассмотреть после проверки установленного альтернативного лаунчера; вернуться на стандартный экран будет нельзя, пока пакет отключён. |
| `com.yandex.tv.alice` | Штатная Алиса в Android. Отключение может устранить конкуренцию голосовых интерфейсов, но штатная Алиса перестанет работать. OpenStation не становится оригинальной Алисой от Яндекса. |
| `com.yandex.tv.daydream` | Штатная заставка. Отключайте, если она не нужна. |
| `com.yandex.tv.music`, `com.yandex.tv.live`, `com.yandex.tv.videoplayer`, `com.yandex.tv.webplayer`, `com.yandex.tv.ytplayer`, `com.yandex.tv.input.efir`, `ru.kinopoisk.yandex.tv` | Штатные медиа и связанные приложения: отключайте только ненужные; соответствующее воспроизведение и интеграции могут исчезнуть. |
| `ru.yandex.androidkeyboard.tv` | Штатная клавиатура. Отключать только после проверки другой работающей клавиатуры и способа обратного включения. |
| `com.yandex.tv.bugreportsender`, `com.yandex.android.advid` | Предположительно отправка отчётов и рекламный идентификатор; возможно влияние на диагностику или совместимость приложений. |
| `com.yandex.tv.setupwizard`, `com.yandex.launcher.updaterapp`, `com.yandex.tv.remotechecker`, `com.yandex.prebuiltstub` | Мастер, обновление или вспомогательные части. Могут понадобиться для восстановления, первого запуска или пульта: без явной причины лучше оставить. |
| `com.yandex.tv.services.platform`, `com.yandex.tv.services`, `com.yandex.io.sdk` | Общие сервисы и SDK; зависимости могут быть широкими. Установщик относит их к отключаемым, но это не доказывает безопасность ручного отключения. Проверяйте особенно осторожно; по умолчанию оставьте включёнными. |

Для проверенного конкретного пакета пример обратимого отключения **для пользователя 0**:

```powershell
adb shell pm disable-user --user 0 com.yandex.tv.daydream
adb shell pm list packages -d
```

Команда меняет состояние устройства. Не применяйте её массово. Для возврата именно этого пакета, если он ранее был включён:

```powershell
adb shell pm enable --user 0 com.yandex.tv.daydream
```

`am force-stop ИМЯ_ПАКЕТА` останавливает приложение сейчас, но не является надёжным постоянным отключением: система может запустить его снова. `pm disable-user` сохраняет отключённое состояние для указанного пользователя. Ни одна из этих команд не удаляет сам APK. Если команда не сработала, не переименовывайте APK в системном разделе: это более рискованное изменение.

### Оставить включённым

В установщике отдельно указано не отключать `ru.yandex.bleremotecontrol`, `com.yandex.tv.settings`, `com.android.tv.settings`, `com.yandex.tv.vendor.config`, `com.yandex.server.SystemExtensionService`. Их фактические зависимости зависят от сборки; ориентир — сохранить управление пультом, настройки и системную конфигурацию.

Также сохраняйте Android `system_server`, `audioserver`, графические службы, драйверы и HAL звука, Wi-Fi и Bluetooth, файловые системы, `adbd` на время настройки и заводские компоненты микрофона/DSP. Особенно не отключайте что-либо только потому, что в имени встречается `yandex`, `vendor`, `audio` или `bluetooth`: среди них могут быть необходимые драйверы и звуковая обработка. Проверка показанного имени в `getprop` не означает, что службу можно останавливать.

`quasard` и другие нативные процессы встречаются на некоторых заводских сборках. Их роль и последствия остановки в этой инструкции не подтверждены: не отключайте их без изучения именно своей системы. Аналогично не удаляйте `/vendor/lib/libyandex_vqe_dsp.so` и устройства `/dev/audiodsp0`, `/dev/amaudio_ctl`: наличие библиотеки и устройств не означает, что их можно безопасно удалить или что отдельный 32-битный мост уже создан. Режим записи `aaudio` и доступность фирменной обработки нужно проверять на устройстве.

## 11. Что можно выключить в самой OpenStation

Предпочтительно использовать настройки веб-пульта: они сохраняют структуру конфигурации и не требуют правки Android. Названия в интерфейсе могут меняться.

| Настройка / поле конфигурации | Можно выключить? | Последствие |
|---|---|---|
| `ledRing.mode = off` | Да | Кольцо не показывает эффекты и индикацию. |
| `ledScreen.mode = off` | Да | Экран станции не показывает часы и визуализаторы. |
| `ledScreen.autoMusicVisualizer = false` | Да | Не будет автоматического перехода к визуализатору музыки. |
| `assistant.enabled = false` или режим `off` | Да | Отключается соответствующий голосовой ассистент. |
| `assistant.wakeWordEnabled = false` | Да | Не ожидайте срабатывания на имя; другие способы активации зависят от конфигурации. |
| `wyoming.enabled = false` | Да, если не нужен | Не работает подключение по Wyoming; в исходном значении включён, порт по умолчанию 10700. |
| `mqtt.enabled = false` | Да, если не нужен | Не работает MQTT-интеграция; по умолчанию выключена. |
| `ota.autoCheck = false` | Да | Не будет автоматической проверки обновлений; сама система не обновится автоматически от этой настройки. |
| `network.wifiAdbEnabled = false` | Да, после проверки другого доступа | Можно потерять сетевой ADB. Штатный способ его запуска зависит от сборки и автозапуска; сначала проверьте USB ADB. |
| `audio.micMuted = true` | Да | Микрофон отключён; голосовой ввод не работает. |
| `audio.aecEnable`, `audio.nsEnable`, `audio.loopbackEnable`, `assistant.echoGuard` | Только для осознанной диагностики | Может ухудшиться разборчивость и появиться самопрослушивание. Не обещайте полноценного AEC от одного переключателя; аппаратный путь зависит от устройства и режима записи. |
| Эквалайзер, эффекты и заставка | Да | Меняется звук или оформление; системные аудиослужбы остаются нужны. |

Фактические значения могут отличаться от значений по умолчанию. Конфигурация находится в `/data/local/openstation/config.json`, её JSON-поля отличаются от названий C++ переменных. При ручном редактировании сначала сделайте резервную копию, остановите демон и проверяйте корректность JSON; запущенный демон может перезаписать файл. Не заменяйте существующую конфигурацию примерами и не публикуйте её: в ней могут быть ключи.

## 12. Типичные проблемы

| Симптом | Что проверить |
|---|---|
| `adb` не найден | Platform Tools, текущую папку и команду `.\adb.exe`. |
| Устройство `offline` или `unauthorized` | Подключение, разрешение отладки и состояние Android. Не переходите к записи разделов только из-за ошибки ADB. |
| `Permission denied` | `adb shell id`, права на файл, путь и особенности Android/SELinux. Не делайте всю систему доступной для записи. |
| Нет процесса после запуска | `boot.log`, `openstationd.log`, архитектуру, наличие библиотек, свободное место, совместимость версии. |
| С ПК открывается веб-пульт, с телефона нет | Одна ли сеть и подсеть, гостевая ли сеть, изоляция клиентов роутера, адрес и порт, мобильный интернет/VPN телефона. |
| Ассистент не отвечает | Включён ли режим, микрофон, голосовые модели, правильный ли ключ, есть ли сеть и доступ к выбранному сервису. |
| Музыка не запускается | Работает ли лаунчер и его аудиосервис, выполнен ли вход, есть ли сеть и ресурс музыкального интерфейса при его необходимости. |
| Пульт не подключается | Не отключена ли штатная служба пульта, работает ли Bluetooth, выполнено ли сопряжение. Не меняйте Bluetooth HAL наугад. |
| После перезагрузки нет OpenStation | Проверьте PID и журнал; ручной запуск не создаёт автозагрузку. |
| Возник бутлуп после прошивки | Эта ADB-инструкция не исправляет загрузчик, разделы или `after_ubt`; не повторяйте запись неизвестных образов без выяснения состояния устройства. |
